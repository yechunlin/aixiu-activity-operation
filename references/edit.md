# 编辑活动流程

> ⚠️ **以下步骤名称为内部流程标记，严禁直接输出给用户。向用户展示时，只输出表格、询问语句和结果信息。**

---

## 支持的输入类型

| 类型        | 格式示例            | 识别规则                    |
|-----------|-----------------|-------------------------|
| **活动 ID** | 32位字符串 或 18位纯数字 | 长度=32（字母+数字）或长度=18（纯数字） |
| **活动链接**  | 含 `http` 或 `/`  | 从链接提取 ID                |
| **活动标题**  | 支持不完整/模糊        | 语义匹配                    |

---

## Step 1：提示用户输入

> 请提供需要编辑的活动ID、活动链接，或活动标题（支持模糊搜索），以及需要修改的内容

---

## Step 2：综合解析输入

对用户输入进行整体解析，拆解为：

- **活动定位信息**：活动ID / 链接 / 标题
- **修改意图**（可选）：要修改的内容类型及新值

解析规则：
1. 先识别活动定位信息（ID > 链接 > 标题）
2. 剩余文本尝试提取修改意图
3. 修改意图可能为空（用户只给了活动ID，没说改什么）

---

## Step 3：活动定位

### 分支A：含 "http" 或 "/" → 链接

- 从链接提取 `act_id`
- 若无法提取：
  > "请提供正确的活动链接（未识别出活动ID）"
  - → 重新进入 Step 1

### 分支B：32位字符串 或 18位纯数字 → 活动ID

- 校验通过：赋值 `act_id`
- 不符合：
  > "请提供正确的活动ID（需为32位字符串或18位数字）"
  - → 重新进入 Step 1

### 分支C：其他 → 活动标题

**匹配范围**（严格限制）：
- 当前会话"最近创建的活动"
- 当前会话"最近编辑的活动"

**匹配规则**：标题包含 或 高语义相似

> ⚠️ **语义匹配操作细则**：
> 1. **匹配阈值**：用户输入与候选标题的语义相似度 ≥ 70% 才视为有效匹配
> 2. **禁止模糊匹配**：以下情况视为匹配失败，不得强行匹配：
>    - 仅情绪词重合（如"好""开心""精彩"）
>    - 活动类型不一致
>    - 核心名词重合度 < 50%
> 3. **Fallback 行为**（匹配失败时）：列出当前会话中最近 3 个活动标题，请用户明确选择；不得猜测，不得自行决定

**结果处理**：

| 结果      | 处理方式                                                                                 |
|---------|--------------------------------------------------------------------------------------|
| 未匹配     | > "未找到相关活动，请提供更完整的标题，或直接提供活动ID/链接" → 重新进入 Step 1                                     |
| 唯一命中    | > "找到活动：「{title}」，是否使用该活动？（是 / 否）" <br> - 确认"是"：使用 `act_id` <br> - 确认"否"：重新进入 Step 1 |
| 多候选（≤5） | 列出候选活动，提示选择或重新输入精确标题                                                                 |

---

## Step 4：获取活动信息

获得 `act_id` 后：
- 调用：`scripts/get_activity.py`
- 参数：`{"act_id": "xxx"}`

**获取失败**：
> "活动未查询到，请确认活动ID或链接后重试"
→ 重新进入 Step 1

**获取成功**：

```json
{
  "act_id": "",
  "act_type": "",
  "title": "",
  "brief": "",
  "start_time": 0,
  "end_time": 0,
  "post_img": {"url": "", "size": "818*1404"},
  "fields": [],
  "scheme": {},
  "is_raffle": 0
}
```

> ⚠️ **必须执行**：将获取到的活动数据**原样保存为 `original_data`**，用于后续对比哪些字段发生了变化。在整个编辑流程中保持不变，直到提交更新完毕。

---

## Step 5：用户确认

**免确认条件**（满足任一条，跳过用户确认）：
- 活动是**当前会话中按时间排序最近**的（最近创建的 或 最近编辑的）

满足免确认时：直接展示活动数据（标题、介绍、字段摘要），**不询问"请确认以上活动信息是否正确"**，直接进入 Step 6 跳转判断

**需要确认的情况**（通过标题模糊匹配命中，非最近那个）：

> "找到活动：「{title}」，是否使用该活动？（是 / 否）"

- 确认语义（是/对/正确/没问题/可以）→ 进入 Step 6
- 否定语义（否/不对/不是这个/错了）→ 重新进入 Step 1
- 语义不明确 → "请明确回复'是'或'否'"

---

## Step 6：跳转判断

如果用户在 Step 1 输入中**已包含明确的修改意图**（已提取到要修改的内容），则：

> **→ 跳过 Step 7，直接进入 Step 8**

否则：

> **→ 进入 Step 7**

---

## Step 7：获取修改需求

> 请说明需要修改的内容（如：标题、活动介绍、活动时间、表单字段等）

接收输入后 → 进入 Step 8（将本轮用户的回答作为修改意图传入）

---

## Step 8：修改意图解析与执行（核心循环）

本步骤为**循环流程**，反复执行直到用户明确结束。同一轮输入中的多个修改意图**一次性处理完毕**，然后统一询问是否继续。单个子项修改完成后不单独询问。

### 8.1 意图识别（可多选，一次性解析）

从用户输入中一次性识别所有修改意图：

| 修改类型      | 识别关键词示例                                        |
|-----------|------------------------------------------------|
| 标题        | "改标题为..."、"标题改成..."                            |
| 活动介绍      | "改介绍"、"修改活动描述为..."、"改简介"                       |
| 活动开始时间    | "改开始时间"、"开始时间改成..."、"提前开始"                     |
| 活动结束时间    | "改结束时间"、"结束时间改成..."、"延期"、"提前结束"                |
| 海报        | "换海报"、"改海报"、"重新设置海报"                           |
| 配色        | "改颜色"、"换风格"、"换配色"、"色调调一下"                      |
| 表单字段      | "添加XX字段"、"增加XX"、"删除XX"、"修改XX"、"去掉XX"           |
| 关联抽奖      | "开抽奖"、"加抽奖"、"关抽奖"、"取消抽奖"                       |

**处理规则**：同一轮输入中若识别到多个修改类型，**全部提取**后统一执行。例如用户说"改标题叫环保行动，再加个手机号字段" → 同时识别出【标题】+【字段新增】。

### 8.2 按类型执行修改

将识别到的所有修改意图，按以下规则**逐项执行**。执行顺序不影响最终结果。

**修改标题**：
- 提取新标题 → 更新 `title = 新标题`

**修改活动介绍**：
- 提取新描述 → 更新 `brief = 新描述`
- **长度约束**：生成或提取的描述建议 50-150 字。若用户提供的描述超过 150 字，须提示："活动介绍过长，建议精简至 150 字以内"
- **边界处理**：`brief` 为空时不得更新，须提示用户："活动介绍缺失，请补充"

**修改海报**：
- 主动询问用户是否有海报图，请提供海报链接
- 用户提供了链接则填充 `{"url": "...", "size": "818*1404"}`，未提供则填充 `{"url": "", "size": "818*1404"}`（结构始终一致，url 为空表示待生成）

**修改配色**：
- 根据 `title` + `brief` 主动生成 `scheme`，参考 `template/designh5.json`

**修改关联抽奖**：
- 增加抽奖 → `is_raffle = 1`
- 取消抽奖 → `is_raffle = 0`

**修改活动开始时间**：
- 提取新时间（支持自然语言或具体日期/时间戳）→ 转换为 Unix 时间戳（秒）→ 更新 `start_time`
- ⚠️ 修改后须重新校验：`start_time < end_time`，若不通过 → 提示："开始时间须早于结束时间，请重新设置"

**修改活动结束时间**：
- 提取新时间 → 转换为 Unix 时间戳（秒）→ 更新 `end_time`
- ⚠️ 修改后须重新校验：`start_time < end_time`，若不通过 → 提示："结束时间须晚于开始时间，请重新设置"

**修改表单字段（fields）**：

字段数据结构：
```json
{
  "type": "Text",
  "label": "姓名",
  "id": "abcdefg1234",
  "placeholder": "请输入姓名",
  "isRequire": true,
  "cid": "c902137408586657792"
}
```

**关键约束**：`id` 和 `cid` 一旦存在，**严禁修改或丢失**。

操作类型识别：
- 新增字段：用户表达"添加""增加""新建"某字段
- 修改字段：用户表达"修改""更改""调整"某字段
- 删除字段：用户表达"删除""移除""去掉"某字段

**A. 新增字段**：
- 参考 `references/field_reference.md` 生成字段结构
- ⚠️ **新增字段不得包含 `id` 和 `cid`**
- 追加到 `fields` 列表

**B. 修改字段**：
1. **定位目标字段**：优先使用 `label` 精确匹配；无法精确匹配时，使用语义匹配（相似度 ≥ 70%，如"姓名"≈"名字"可匹配）
2. **执行修改**：仅允许修改 `label`、`type`、`placeholder`、`isRequire`、其他展示属性；**必须保留** `id` 和 `cid` 不变
3. **匹配失败 Fallback**：列出当前 `fields` 所有字段的 `label`，请用户明确指定；不得猜测，不得自行决定
4. **禁止行为**：不得仅凭情绪词或通用词定位字段；不得匹配到多个字段时不加区分地全部修改

**C. 删除字段**：
1. 定位目标字段（通过 `label` 或语义匹配）
2. **必须向用户确认**："确认要删除字段【字段名】吗？（是/否）"
   - 用户回复"是" → 继续下一步
   - 用户回复"否" → 取消删除，保持原字段
3. 从 `fields` 中移除

**D. 一致性校验（必须执行）**：

每次字段修改后校验：

| 校验项     | 要求                                      |
|---------|-----------------------------------------|
| 已有字段    | 必须包含 `id` 和 `cid`，且值不变                  |
| 新增字段    | 不得包含 `id` 和 `cid`                       |
| 整体结构    | 符合 `references/field_reference.md` 格式规范 |
| 禁止      | 字段结构错乱、缺失关键属性、类型异常                      |

校验失败 → "字段结构异常，请重新调整修改内容"

### 8.3 单轮修改完成后

> ⚠️ **强制约束：无论通过何种路径，修改完成后必须进入 Step 9 等待用户最终确认，严禁直接提交更新**

**跳转判断**：
- 若 **Step 1 已提取到完整修改意图**（从 Step 6 直接进入本步骤，且所有要修改的内容都已识别并执行完毕）→ **跳过"是否还需要修改其他内容"的询问，直接进入 Step 9**
- 否则 → 询问用户：

> "当前修改已完成，请问还需要修改其他内容吗？（是 / 否）"

| 用户回复       | 处理                            |
|------------|-------------------------------|
| "是"（或语义等价） | 继续循环，返回步骤 8.1                 |
| "否"（或语义等价） | 结束循环，进入 Step 9                |
| 语义不明确      | "请回复'是'或'否'"                  |

---

## Step 9：确认修改活动

提交更新前，必须执行数据预校验（未通过不得进入确认环节）：

| 校验项          | 校验范围        | 校验规则                                 | 不通过处理                           |
|--------------|-------------|--------------------------------------|---------------------------------|
| `title`      | 仅当字段存在且被修改时 | 非空，长度 2-15 字符                        | 提示"活动标题缺失或过长，请返回修改"，终止本步骤       |
| `brief`      | 仅当字段存在且被修改时 | 非空，长度 50-150 字符                      | 提示"活动介绍缺失或过长，请返回修改"，终止本步骤       |
| `start_time` | 仅当字段存在且被修改时 | 为有效 Unix 时间戳（秒），且 `< end_time`       | 提示"活动开始时间无效或晚于结束时间，请重新设置"，终止本步骤 |
| `end_time`   | 仅当字段存在且被修改时 | 为有效 Unix 时间戳（秒），且 `> start_time`     | 提示"活动结束时间无效或早于开始时间，请重新设置"，终止本步骤 |
| `fields`     | 始终校验（如字段存在） | 已有字段须含 `id`+`cid`，新增字段不含 `id`+`cid`  | 提示"字段结构异常，请重新修改"，终止本步骤          |
| `post_img`   | 仅当字段存在且被修改时 | 含 `url`（可为空字符串）和 `size` 字段           | 提示"海报数据结构异常，请重新设置"，终止本步骤        |
| JSON 整体合法性   | 始终校验        | 可被 JSON.stringify 无报错                | 提示"活动数据格式异常，请联系技术人员"，终止本步骤      |

✅ 校验全部通过后，**仅展示发生变化的项**（对比 `original_data`，无变动的不展示）：

- 标题有变化 → 活动标题（原：{original_data.title} → 新：{title}）
- 介绍有变化 → 活动介绍（原：{original_data.brief} → 新：{brief}）
- 开始时间有变化 → 活动开始时间（原：{original_data.start_time 转日期} → 新：{start_time 转日期}）
- 结束时间有变化 → 活动结束时间（原：{original_data.end_time 转日期} → 新：{end_time 转日期}）
- 字段有变化 → 报名字段（{fields 摘要}）
- 海报有变化 → 海报（{post_img 摘要}）
- 配色有变化 → 配色（已更新）
- 抽奖有变化 → 关联抽奖（{is_raffle = 1 ? "是" : "否"}）

展示后询问用户：

> "是否确认更新活动？（是 / 否）"

- "是"（或语义等价）→ 进入 Step 10
- "否" → 返回 Step 8 继续修改
- 语义不明确 → "请回复'是'或'否'"

---

## Step 10：提交更新

1. **写入临时文件**
   - 生成路径：`temp_file_path`
   - 写入内容格式：
   ```json
   {
      "act_id": "活动ID",
      "act_type": "活动类型",
      "title": "",
      "brief": "",
      "start_time": 0,
      "end_time": 0,
      "post_img": {"url": "", "size": "818*1404"},
      "fields": [],
      "scheme": {},
      "is_raffle": 0
   }
   ```

2. **调用接口**
   - 脚本：`scripts/update_event.py`
   - 参数：`{"temp_file_path": "xxx"}`

3. **返回结果处理**

**修改失败**：
> "活动更新失败，请稍后重试"
（流程结束）

**修改成功**：

必须向用户展示以下所有信息（缺一不可）：
- 活动标题：`title`
- 活动链接：`url`
- 平台信息：`platform`（必须完整展示，不得省略或隐藏）
- 二维码图片：`qr_code`（大小：200 * 200，优先 Markdown 语法 `![二维码]({qr_code})`；不支持则 `<img>`；均不支持则直接展示链接）

展示格式：

```
标题：{title}
活动地址：{url}
平台：{platform}
二维码图片：![二维码]({qr_code})
```

> 活动更新成功！
> 可浏览打开二维码，使用微信扫码体验活动！
